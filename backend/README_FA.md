# راه‌اندازی بک‌اند MATINEX GAMING

این پوشه، اسکلت اولیه بک‌اند فروشگاه است؛ هنوز به سایت عمومی متصل یا روی سرور منتشر نشده است.

## چه چیزهایی آماده شده؟
- جدول محصولات با قیمت به تومان
- جدول سفارش‌ها و اقلام سفارش
- سیاست‌های دسترسی پایگاه‌داده (RLS)
- تابع سروری ساخت سفارش با احراز هویت مشتری
- محاسبه مبلغ از قیمت ثبت‌شده در پایگاه‌داده، نه از مبلغ ارسالی مرورگر

## چه چیزهایی هنوز انجام نشده؟
- ساخت پروژه میزبانی و پایگاه‌داده
- اتصال فرم ورود/ثبت‌نام سایت به احراز هویت واقعی
- وارد کردن محصولات و قیمت‌های تأییدشده
- اتصال رابط کاربری به API
- انتخاب و اتصال درگاه پرداخت ایرانی
- تأیید امضای callback درگاه و تغییر وضعیت سفارش به paid
- تحویل امن کد یا محصول دیجیتال

## نکات امنیتی مهم
1. کلید `SUPABASE_SERVICE_ROLE_KEY` فقط باید در Secrets سمت سرور قرار بگیرد. هرگز آن را در `index.html`، GitHub Pages یا کد مرورگر قرار نده.
2. وضعیت سفارش فقط پس از تأیید سروری و مستقل پرداخت‌یار باید به `paid` تغییر کند؛ بازگشت کاربر به صفحه موفقیت به‌تنهایی مدرک پرداخت نیست.
3. برای هر محصول فقط محتوای اورجینال یا دارای مجوز فروش عرضه کن. خریدوفروش حساب کاربری یا کدهای نامعتبر/منطقه‌ای می‌تواند باعث مسدودی و مشکل حقوقی شود.
4. چون صاحب پروژه زیر ۱۸ سال است، ایجاد حساب‌های تجاری، قرارداد میزبانی/درگاه و امور بانکی باید با مسئولیت و نظارت ولی یا سرپرست قانونی انجام شود.
5. پیش از انتخاب سرویس، دسترسی و شرایط استفاده آن از داخل ایران و سازگاری آن با پرداخت و تسویه ریالی باید بررسی شود.

## مراحل بعدی
- یک بزرگسال مسئول، حساب سرویس پایگاه‌داده و میزبانی سازگار و مجاز ایجاد کند.
- فایل `schema.sql` را در SQL Editor پروژه اجرا کند.
- تابع `create-order` را با Secrets سمت سرور منتشر کند:
  - `SUPABASE_URL`
  - `SUPABASE_ANON_KEY`
  - `SUPABASE_SERVICE_ROLE_KEY`
  - `SITE_URL`
- پس از فراهم شدن اطلاعات اتصال، فرانت‌اند را به این API وصل می‌کنیم.
- درگاه پرداخت فقط بعد از تعیین فروشنده قانونی، مجوزهای لازم و مستندات رسمی API اضافه می‌شود.

**این کد پرداخت انجام نمی‌دهد و نباید برای دریافت پول واقعی استفاده شود تا مراحل پرداخت و تأیید سمت سرور کامل و آزمایش شوند.**


## امکانات جدید رابط کاربری (نسخه نمایشی)
- مرتب‌سازی بازی‌ها بر اساس ارزان‌ترین و گران‌ترین قیمت پایه دلاری.
- مرکز پشتیبانی با پرسش‌های پرتکرار.
- فرم ثبت پیام پشتیبانی و مشاهده پیام‌ها در پنل مدیریت؛ فعلاً فقط localStorage همان مرورگر.
- جست‌وجوی شماره سفارش آزمایشی؛ فقط سفارش‌های ثبت‌شده در همان مرورگر پیدا می‌شوند.
- جدول‌های آماده پروفایل کاربر و تیکت پشتیبانی با RLS در `schema.sql` اضافه شده‌اند.

## وضعیت واقعی انتشار
این commitها فقط کد مخزن GitHub را به‌روز می‌کنند. پروژه Supabase، احراز هویت، پایگاه داده آنلاین، پنل مدیریت مرکزی و درگاه پرداخت هنوز ایجاد/منتشر/متصل نشده‌اند. بنابراین:
- هیچ ثبت‌نام واقعی یا حساب مرکزی فعال نیست.
- پیام پشتیبانی به اپراتور ارسال نمی‌شود.
- سفارش‌ها بین دستگاه‌های مختلف همگام نمی‌شوند.
- پرداخت یا تحویل کالای پولی انجام نمی‌شود.

برای فعال‌سازی مرحله سرور، مالک بزرگسال پروژه باید یک پروژه Supabase مجاز بسازد، SQL را اجرا کند، Edge Function را منتشر کند و اطلاعات عمومی اتصال را در پیکربندی فرانت‌اند قرار دهد. کلید Service Role فقط در Secrets سمت سرور می‌ماند و هرگز نباید در سایت یا چت قرار گیرد. انتخاب درگاه و امور بانکی/قراردادی نیز باید با مسئولیت ولی یا سرپرست قانونی انجام شود. اطلاعات بانکی، رمزها یا کلیدهای محرمانه را در این گفتگو ارسال نکن.
