# راه‌اندازی بک‌اند MATINEX GAMING

این پوشه، اسکلت اولیه بک‌اند فروشگاه است؛ هنوز به سایت عمومی متصل یا روی سرور منتشر نشده است.

## چه چیزهایی آماده شده؟
- جدول محصولات با قیمت به تومان
- جدول سفارش‌ها و اقلام سفارش
- سیاست‌های دسترسی پایگاه‌داده (RLS)
- تابع سروری ساخت سفارش با احراز هویت مشتری
- محاسبه مبلغ از قیمت ثبت‌شده در پایگاه‌داده، نه از مبلغ ارسالی مرورگر

## چه چیزهایی هنوز انجام نشده؟
- ساخت پروژه میزبانی و پایگاه‌داده
- اتصال فرم ورود/ثبت‌نام سایت به احراز هویت واقعی
- وارد کردن محصولات و قیمت‌های تأییدشده
- اتصال رابط کاربری به API
- انتخاب و اتصال درگاه پرداخت ایرانی
- تأیید امضای callback درگاه و تغییر وضعیت سفارش به paid
- تحویل امن کد یا محصول دیجیتال

## نکات امنیتی مهم
1. کلید `SUPABASE_SERVICE_ROLE_KEY` فقط باید در Secrets سمت سرور قرار بگیرد. هرگز آن را در `index.html`، GitHub Pages یا کد مرورگر قرار نده.
2. وضعیت سفارش فقط پس از تأیید سروری و مستقل پرداخت‌یار باید به `paid` تغییر کند؛ بازگشت کاربر به صفحه موفقیت به‌تنهایی مدرک پرداخت نیست.
3. برای هر محصول فقط محتوای اورجینال یا دارای مجوز فروش عرضه کن. خریدوفروش حساب کاربری یا کدهای نامعتبر/منطقه‌ای می‌تواند باعث مسدودی و مشکل حقوقی شود.
4. چون صاحب پروژه زیر ۱۸ سال است، ایجاد حساب‌های تجاری، قرارداد میزبانی/درگاه و امور بانکی باید با مسئولیت و نظارت ولی یا سرپرست قانونی انجام شود.
5. پیش از انتخاب سرویس، دسترسی و شرایط استفاده آن از داخل ایران و سازگاری آن با پرداخت و تسویه ریالی باید بررسی شود.

## مراحل بعدی
- یک بزرگسال مسئول، حساب سرویس پایگاه‌داده و میزبانی سازگار و مجاز ایجاد کند.
- فایل `schema.sql` را در SQL Editor پروژه اجرا کند.
- تابع `create-order` را با Secrets سمت سرور منتشر کند:
  - `SUPABASE_URL`
  - `SUPABASE_ANON_KEY`
  - `SUPABASE_SERVICE_ROLE_KEY`
  - `SITE_URL`
- پس از فراهم شدن اطلاعات اتصال، فرانت‌اند را به این API وصل می‌کنیم.
- درگاه پرداخت فقط بعد از تعیین فروشنده قانونی، مجوزهای لازم و مستندات رسمی API اضافه می‌شود.

**این کد پرداخت انجام نمی‌دهد و نباید برای دریافت پول واقعی استفاده شود تا مراحل پرداخت و تأیید سمت سرور کامل و آزمایش شوند.**


## امکانات جدید رابط کاربری (نسخه نمایشی)
- مرتب‌سازی بازی‌ها بر اساس ارزان‌ترین و گران‌ترین قیمت پایه دلاری.
- مرکز پشتیبانی با پرسش‌های پرتکرار.
- فرم ثبت پیام پشتیبانی و مشاهده پیام‌ها در پنل مدیریت؛ فعلاً فقط localStorage همان مرورگر.
- جست‌وجوی شماره سفارش آزمایشی؛ فقط سفارش‌های ثبت‌شده در همان مرورگر پیدا می‌شوند.
- جدول‌های آماده پروفایل کاربر و تیکت پشتیبانی با RLS در `schema.sql` اضافه شده‌اند.

## وضعیت واقعی انتشار
این commitها فقط کد مخزن GitHub را به‌روز می‌کنند. پروژه Supabase، احراز هویت، پایگاه داده آنلاین، پنل مدیریت مرکزی و درگاه پرداخت هنوز ایجاد/منتشر/متصل نشده‌اند. بنابراین:
- هیچ ثبت‌نام واقعی یا حساب مرکزی فعال نیست.
- پیام پشتیبانی به اپراتور ارسال نمی‌شود.
- سفارش‌ها بین دستگاه‌های مختلف همگام نمی‌شوند.
- پرداخت یا تحویل کالای پولی انجام نمی‌شود.

برای فعال‌سازی مرحله سرور، مالک بزرگسال پروژه باید یک پروژه Supabase مجاز بسازد، SQL را اجرا کند، Edge Function را منتشر کند و اطلاعات عمومی اتصال را در پیکربندی فرانت‌اند قرار دهد. کلید Service Role فقط در Secrets سمت سرور می‌ماند و هرگز نباید در سایت یا چت قرار گیرد. انتخاب درگاه و امور بانکی/قراردادی نیز باید با مسئولیت ولی یا سرپرست قانونی انجام شود. اطلاعات بانکی، رمزها یا کلیدهای محرمانه را در این گفتگو ارسال نکن.


## توابع تکمیلی آماده انتشار
دو تابع امن دیگر به پوشه Supabase اضافه شده‌اند:
- `create-support-ticket`: فقط کاربر واردشده می‌تواند تیکت برای حساب خودش بسازد؛ عنوان و متن اعتبارسنجی می‌شوند و درج با سیاست RLS انجام می‌شود.
- `list-my-orders`: فقط سفارش‌های حساب واردشده را (حداکثر ۵۰ سفارش آخر، همراه اقلام) برمی‌گرداند؛ محدودیت مالکیت با RLS پایگاه‌داده اعمال می‌شود.

برای انتشار هر تابع:
```bash
supabase functions deploy create-support-ticket
supabase functions deploy list-my-orders
```
این دستورات را فقط پس از نصب Supabase CLI، ورود مسئول بزرگسال به پروژه خودش و اتصال پوشه به همان پروژه اجرا کنید. این دو تابع هنوز منتشر یا به رابط سایت وصل نشده‌اند.

### چک‌لیست پیش از فروش واقعی
- [ ] پروژه Supabase ایجاد و منطقه/شرایط سرویس بررسی شود.

- [ ] Secrets سمت سرور تنظیم و هر سه Edge Function منتشر شوند.

- [ ] درگاه پرداخت قانونی و مجاز انتخاب و callback امضاشده سمت سرور پیاده‌سازی شود.

- [ ] تحویل دیجیتال فقط برای محصولات مجاز و پس از تأیید قطعی پرداخت فعال شود.

**وضعیت فعلی:** کدهای فوق در مخزن آماده‌اند؛ سرویس ابری، کلیدها، احراز هویت، اتصال فرانت‌اند و پرداخت واقعی هنوز فعال نیستند.


## مدیریت امن تیکت‌ها
- تابع `admin-update-ticket` فقط به حساب‌هایی اجازه تغییر وضعیت تیکت می‌دهد که شناسه کاربری آن‌ها در جدول `admin_users` ثبت شده باشد.
- پس از ساخت حساب مدیر در Supabase Auth، مسئول بزرگسال باید شناسه UUID همان حساب را با SQL و به‌صورت دستی در جدول `admin_users` وارد کند. هیچ مسیر عمومی برای ثبت مدیر وجود ندارد.
- انتشار تابع:
```bash
supabase functions deploy admin-update-ticket
```
- این تابع از `SUPABASE_SERVICE_ROLE_KEY` فقط در محیط سرور استفاده می‌کند و پیش از هر تغییر، JWT و عضویت مدیر را بررسی می‌کند.
- این نسخه فقط تغییر وضعیت تیکت را پیاده‌سازی می‌کند؛ هنوز داشبورد مرکزی مدیریت سفارش‌ها/محصولات در فرانت‌اند ساخته و متصل نشده است.


## ابزارهای پنل مدیریت سمت سرور
توابع زیر برای استفاده از یک داشبورد مدیریتی امن آماده شده‌اند:
- `admin-save-product` (POST): ساخت یا ویرایش محصول با اعتبارسنجی شناسه، نام، قیمت تومان و وضعیت انتشار.
- `admin-list-tickets` (GET): دریافت حداکثر ۱۰۰ تیکت اخیر برای مدیر تأییدشده.
- `admin-list-orders` (GET): دریافت حداکثر ۱۰۰ سفارش اخیر همراه اقلام سفارش برای مدیر تأییدشده.

انتشار:
```bash
supabase functions deploy admin-save-product
supabase functions deploy admin-list-tickets
supabase functions deploy admin-list-orders
```

تمام توابع مدیریتی ابتدا کاربر را با Supabase Auth اعتبارسنجی و سپس عضویت او را در `admin_users` بررسی می‌کنند. کلید Service Role فقط در محیط امن Edge Function استفاده می‌شود. این APIها هنوز از داشبورد وب فراخوانی نمی‌شوند و صرفاً کد سمت سرور آماده شده است.

**نکته امنیتی:** حساب مدیر را فقط مسئول مجاز پروژه و پس از احراز هویت مالک کسب‌وکار به allow-list اضافه کند. دسترسی مدیر را از مرورگر یا فرم عمومی قابل اعطا نکنید.


## اتصال رابط سایت به Supabase (رابط کاربری به‌روزشده)
در نسخه فعلی `index.html` این بخش‌ها به‌صورت آماده اتصال اضافه شده‌اند:
- فرم تنظیم آدرس پروژه و کلید عمومی anon/publishable در پنجره حساب کاربری.
- ورود با ایمیل/رمز و ثبت‌نام از طریق Supabase Auth.
- ثبت تیکت از طریق تابع `create-support-ticket` در صورت اتصال و ورود.
- پیگیری سفارش با تابع `list-my-orders` برای کاربر واردشده.
- فرم افزودن محصول در داشبورد مدیریت با تابع `admin-save-product`.
- بارگذاری سفارش‌ها و تیکت‌های سرور از توابع مدیریتی؛ مدیر می‌تواند وضعیت تیکت را تغییر دهد.

### راه‌اندازی توسط مسئول پروژه
1. پروژه Supabase را ایجاد کنید و `schema.sql` را اجرا کنید.
2. در تنظیمات Authentication، نشانی سایت Pages را به فهرست مجاز Redirect URLs اضافه کنید.
3. توابع را منتشر کنید:
```bash
supabase functions deploy create-order
supabase functions deploy create-support-ticket
supabase functions deploy list-my-orders
supabase functions deploy admin-update-ticket
supabase functions deploy admin-save-product
supabase functions deploy admin-list-tickets
supabase functions deploy admin-list-orders
```
4. برای هر تابع مدیریتی و هر تابعی که به Service Role نیاز دارد، Secrets سمت سرور را تنظیم کنید؛ Service Role هرگز در مرورگر قرار نمی‌گیرد.
5. حساب مدیر را از مسیر Auth ایجاد کنید و فقط پس از بررسی، UUID آن را از SQL Editor به جدول `admin_users` اضافه کنید.
6. در سایت، پنجره حساب کاربری را باز کنید و آدرس پروژه و کلید عمومی anon/publishable را وارد کنید. این کلید عمومی برای استفاده مرورگر طراحی شده و امنیت داده‌ها باید با RLS و Edge Functions اعمال شود.
7. برای ثبت تیکت و پیگیری سفارش، کاربر باید وارد حساب شود. برای عملیات مدیریتی، حساب باید در `admin_users` مجاز شده باشد.

**محدودیت‌های باقی‌مانده:** این commit فقط رابط و اتصال کلاینت را آماده کرده است. تا زمانی که یک پروژه واقعی Supabase ایجاد، SQL اجرا، توابع منتشر و کلید عمومی در سایت تنظیم نشود، حساب‌ها/تیکت‌ها/سفارش‌های سروری فعال نخواهند شد. ساختار پرداخت و callback درگاه هنوز پیاده‌سازی نشده است؛ هیچ سفارش پرداخت‌شده یا تحویل خودکار محصول را فعال نکنید.


## مدیریت فهرست محصولات از پنل مالک
- تابع `admin-list-products` فقط برای حساب‌های عضو جدول `admin_users` فهرست حداکثر ۲۰۰ محصول را برمی‌گرداند.
- در پنل مالک، دکمه «مدیریت محصولات سرور» فهرست را بارگذاری می‌کند؛ «ویرایش» فرم محصول را پر می‌کند و «فعال‌سازی/غیرفعال‌سازی» وضعیت انتشار را از طریق تابع امن `admin-save-product` تغییر می‌دهد.
- برای انتشار تابع جدید:
```bash
supabase functions deploy admin-list-products
```
- این تابع از کلید Service Role فقط در محیط Edge Function استفاده می‌کند و پیش از خواندن فهرست، نشست کاربر و عضویت مدیر را بررسی می‌کند.
- غیرفعال‌سازی به‌جای حذف دائمی ارائه شده تا سابقه محصول و ارجاع احتمالی سفارش‌ها از بین نرود.
- تا زمانی که تابع روی پروژه Supabase واقعی منتشر نشده باشد، دکمه فهرست محصولات سرور کار نخواهد کرد.

- شناسه کاربر از JWT معتبر Supabase گرفته می‌شود و فیلتر مالکیت در کوئری اعمال می‌شود؛ RLS جدول نیز همچنان فعال است.

- انتشار تابع:
```bash
supabase functions deploy list-my-support-tickets
```
- این امکان فقط پس از اجرای schema، انتشار تابع و ورود کاربر در پروژه Supabase واقعی فعال می‌شود.
