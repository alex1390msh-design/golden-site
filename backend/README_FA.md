# راه‌اندازی و وضعیت فنی MATINEX GAMING

این فایل وضعیت واقعی کدها و مراحل راه‌اندازی را ثبت می‌کند. **وجود کد در GitHub به معنی فعال بودن سرویس ابری نیست.**

## وضعیت فعلی

### آماده در مخزن GitHub
- رابط فروشگاه فارسی و راست‌چین، جست‌وجو، فیلتر، جزئیات، علاقه‌مندی و مقایسه بازی‌ها.
- سبد خرید و ثبت سفارش آزمایشی محلی؛ بدون دریافت وجه.
- معرفی محصولات سرور از جدول `products` در صورت اتصال Supabase.
- فرم ورود و ثبت‌نام متصل‌شونده به Supabase Auth.
- مرکز پشتیبانی، ثبت تیکت، مشاهده تاریخچه تیکت‌های مشتری و ابزار مدیریت تیکت‌ها.
- داشبورد مدیریت محصولات سرور: ایجاد، ویرایش، فعال‌سازی و غیرفعال‌سازی.
- مشاهده سفارش‌ها و تیکت‌های سرور برای حساب‌های مجاز مدیر.
- نرخ تبدیل دلار به تومان با مقدار مرجع قابل ویرایش دستی؛ **نرخ زنده بازار نیست**.

### هنوز فعال نشده / نیازمند راه‌اندازی بیرونی
- پروژه Supabase، پایگاه‌داده و Edge Functionها هنوز باید توسط مسئول پروژه ایجاد و منتشر شوند.
- محصولات واقعی باید با قیمت معتبر و مجوز فروش در جدول پایگاه‌داده وارد شوند.
- درگاه پرداخت، callback امضاشده، تأیید پرداخت و تحویل امن دیجیتال پیاده‌سازی نشده‌اند.
- فایل‌های حجیم بازی‌ها روی GitHub Pages میزبانی نمی‌شوند؛ فقط محتوای دارای مجوز توزیع می‌تواند روی زیرساخت مناسب قرار بگیرد.

## ساختار فایل‌ها
- `supabase/schema.sql`: جدول‌ها، کلیدهای خارجی، ایندکس‌ها و سیاست‌های RLS.
- `supabase/functions/`: توابع Edge سمت سرور.
- `../index.html`: رابط وب عمومی.

## جدول‌ها و امنیت داده
- `products`: محصولات و قیمت تومانی؛ خواندن عمومی فقط برای محصولات فعال.
- `orders` و `order_items`: سفارش‌ها و اقلام؛ مشتری فقط سفارش‌های خودش را می‌خواند.
- `profiles`: نام نمایشی حساب؛ رمز عبور در این جدول ذخیره نمی‌شود.
- `support_tickets`: تیکت‌ها؛ مشتری فقط تیکت‌های خودش را می‌خواند و ایجاد تیکت از مسیر احراز هویت‌شده انجام می‌شود.
- `admin_users`: فهرست مجاز مدیرها؛ هیچ مسیر عمومی برای افزودن مدیر وجود ندارد.

فایل `schema.sql` را در SQL Editor یک پروژه تازه Supabase اجرا کنید. اگر قبلاً بخشی از جدول‌ها را دستی ساخته‌اید، پیش از اجرای دوباره، ساختار موجود را بررسی کنید.

## توابع Edge موجود

| تابع | روش | کاربرد |
|---|---|---|
| `create-order` | POST | ساخت سفارش از قیمت ذخیره‌شده در پایگاه‌داده |
| `create-support-ticket` | POST | ثبت تیکت برای کاربر واردشده |
| `list-my-orders` | GET | نمایش حداکثر ۵۰ سفارش خود کاربر |
| `list-my-support-tickets` | GET | نمایش حداکثر ۵۰ تیکت خود کاربر |
| `admin-update-ticket` | POST | تغییر وضعیت تیکت توسط مدیر مجاز |
| `admin-save-product` | POST | ساخت یا ویرایش محصول توسط مدیر مجاز |
| `admin-list-products` | GET | دریافت حداکثر ۲۰۰ محصول برای مدیر |
| `admin-list-tickets` | GET | دریافت حداکثر ۱۰۰ تیکت برای مدیر |
| `admin-list-orders` | GET | دریافت حداکثر ۱۰۰ سفارش برای مدیر |

برای انتشار، مسئول پروژه پس از نصب Supabase CLI، ورود به پروژه درست و تنظیم Secrets، این دستورات را اجرا می‌کند:

```bash
supabase functions deploy create-order
supabase functions deploy create-support-ticket
supabase functions deploy list-my-orders
supabase functions deploy list-my-support-tickets
supabase functions deploy admin-update-ticket
supabase functions deploy admin-save-product
supabase functions deploy admin-list-products
supabase functions deploy admin-list-tickets
supabase functions deploy admin-list-orders
```

## تنظیمات اتصال

در محیط Edge Functions، متغیرهای لازم را با مقادیر پروژه خود تنظیم کنید:
- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY` فقط برای توابع مدیریتی/سفارشی که به دسترسی ممتاز نیاز دارند.
- `SITE_URL` برابر با مبدأ مجاز سایت، برای نمونه `https://alex1390msh-design.github.io`.

در تنظیمات Authentication، نشانی سایت و مسیرهای بازگشت لازم را در فهرست مجاز Redirect URLs ثبت کنید. در رابط سایت، پنجره حساب کاربری را باز کرده و Project URL و کلید عمومی anon/publishable را وارد کنید.

**کلید Service Role را هرگز در سایت، فایل `index.html`، GitHub، مرورگر یا چت وارد نکنید.** فقط کلید عمومی anon/publishable برای مرورگر است؛ امنیت داده‌ها به RLS و اعتبارسنجی سمت سرور وابسته است.

## فعال‌سازی مدیر
1. حساب مدیر را از مسیر Auth ایجاد کنید.
2. شناسه UUID همان حساب را از داشبورد پروژه بردارید.
3. فقط مسئول مجاز پروژه، پس از بررسی هویت و اختیار، UUID را در SQL Editor به جدول `admin_users` اضافه کند.
4. حساب مدیر باید با همان ایمیل در سایت وارد شود.
5. هیچ‌وقت برای راحتی، امکان ثبت‌نام عمومی مدیر یا قرار دادن رمز ثابت در کد مرورگر ایجاد نکنید.

## محدودیت سفارش و پرداخت
- سبد خرید فعلی و سفارش‌های محلی، نمایشی‌اند و بین دستگاه‌ها همگام نمی‌شوند.
- تابع `create-order` می‌تواند سفارش pending را با قیمت پایگاه‌داده بسازد؛ این کار پرداخت را انجام نمی‌دهد.
- **هیچ سفارشی را صرفاً با بازگشت کاربر به صفحه موفقیت، paid نکنید.**
- پرداخت واقعی نیازمند فروشنده قانونی، درگاه مجاز، اعتبارسنجی امضای callback در سرور، جلوگیری از پرداخت تکراری و ثبت امن نتیجه است.
- تحویل دیجیتال فقط برای کالای دارای حق توزیع و پس از تأیید قطعی پرداخت باید فعال شود.
